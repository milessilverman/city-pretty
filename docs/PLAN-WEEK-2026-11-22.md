# Week plan, 22-28 Nov 2026: from checked data to "what to do, where, at what cost"

Owner's ask (22 Nov): use this week's capacity fully; keep accuracy first; use the Gemini and ChatGPT subscriptions
where they help; end the week able to show, for a place, the different courses of action, what each costs, and a
property-value prediction that has earned its confidence. Longer plan: `PLAN-DEVELOPER-PLATFORM.md`.

## 1. What the week must deliver

For a station area, a drawn area or a single site, a **project card** with two to four courses of action, for example:

| Course | What it is |
|---|---|
| Hold and earn | Buy, keep as is, rent every space (parking, storage, roof) while plans and permits run |
| Small infill | What state law and zoning on file allow on the lots: ADUs, lot splits, small multifamily |
| Station-area build | Multifamily on the redevelopment sites, conventional vs prefabricated, with an affordable share |
| Partner on the transit | The build above plus a share of the line's cost recovered through value capture and joint development |

Each course shows: what is built and where; cost as a range from sourced unit costs; public money that applies under
its own rules; yearly income; the value prediction with its tested error; what could break it; what data is missing.
"I have $X" filters and ranks the cards. Arithmetic is done by scripts; the advisor explains and compares.

## 2. The prediction: what will make it good, and how we will know

Today's neighborhood ranking is no better than "pick the cheapest areas" out of sample. This week it gets leading
signals that are free, national and dated, so they can be tested on the past:

| Signal | Source | Why it should lead prices |
|---|---|---|
| Mortgage applications and loan amounts by tract, by year | CFPB HMDA public data | Buyers and money arriving before prices show it |
| Building permits by place and county, monthly | Census Building Permits Survey | Supply coming, and builders' own bets |
| Jobs by block, by year | Census LODES | Job growth nearby |
| ZIP-level home values and rents, monthly | Zillow ZHVI and ZORI (terms to confirm) | Momentum at a finer grain than the tract index |
| Tract price index, yearly | FHFA | Outcome variable, and prior trend |
| Address vacancy by tract, quarterly | HUD/USPS (access to confirm) | Emptying or filling up |
| Household moves by county | IRS migration data | Demand shifting between metros |
| Planned stations and their stage | The corridor table, FTA project profiles | The uplift studies say when value moves |

Method, fixed before any result is seen: walk-forward tests (fit on years up to T, predict T to T+3 and T+5, roll
forward), several start years, results by metro; compare with two baselines (cheapest areas; prior trend). The page
shows a predicted range from the model's own past errors, and the hit rate beside it. If the model does not beat the
baselines in a county, that county says so and shows the baseline. A prediction is never shown without its test.

Site-level value comes from the tested county valuation models where they passed; elsewhere it is withheld.

## 3. Costs: sourced, ranged, dated

- Buildings: ICC Building Valuation Data by type, regional factors, state housing-agency cost limits and LIHTC cost
  reports, prefab case studies (research prompt 1). RSMeans only if these prove too coarse.
- Streets and utilities: state DOT bid prices and utility fee schedules (prompt 10); StreetForge takes over later.
- Transit: capital cost per mile from the benchmark table; operating cost and fare revenue per trip from the National
  Transit Database (prompt 4); ridership from published station-level models, tested on existing stations (prompt 3).
- Public money: each programme's own share and eligibility rules (prompts 5 and 6).
- Every cost is a range with its year and place. A course whose cost has no source shows "cost not on file".

## 4. Using Gemini and ChatGPT

They are used for three things, and never as a source:

1. **Research at volume.** Run each prompt in `RESEARCH-PROMPTS.md` in both tools' deep-research modes. Two
   independent answers per prompt: where they agree with matching quotes, a cheap agent re-fetches a sample and loads
   the table; where they disagree, the item is settled at the primary source or left out.
2. **Fetching what this build machine cannot reach** (federal rail and transit sites, Amtrak, California bill text,
   California High-Speed Rail): have them download the documents; drop the files in a shared Google Drive folder
   that this session can read.
3. **Red-team review.** Give either tool a finished project card or data table and ask it to find errors with
   sources. Every claimed error is checked at the source before anything changes.

Rule: nothing from another model enters a data file until its quote has been matched in a document fetched by this
project's own scripts, or in a file the owner supplied from the official site.

## 5. Running the week without waste

Problems seen so far: two sessions doing the same job on different branches; six or more agents at once exhausting
the five-hour allowance and the machine's memory; Fable's separate limit stopping the interface work.

- **One trunk** (`claude/nifty-wozniak-tl4d5g`), one integrating session. Any other session works on its own branch,
  from the trunk's tip, on a lane written in `WORK-QUEUE.md` before it starts, and ends with a handoff file.
- **Lanes by model.** Sonnet and Haiku: loading research answers, county builds, link and quote checks (run
  continuously, including overnight). Opus: models, merges, reviews. Fable: interface and the prediction design only.
- **At most three agents at once in one container**, one full browser suite at a time.
- **Overnight session** keeps the small-county builds and data loading going; the day session integrates and builds
  the models.

## 7. What "accurate" means for the demo

| Shown | Test it must pass first |
|---|---|
| Value prediction for an area | Walk-forward error and hit rate vs both baselines, shown beside it |
| Ridership for a proposed station | Model error on existing stations of the same mode |
| Build cost | Within the range of real project costs on file for that state and type |
| Public funding share | Each programme's rule quoted from its statute or guidance |
| Law-based unit counts | Statute record confirmed, including its exclusions; else "not determined" |
